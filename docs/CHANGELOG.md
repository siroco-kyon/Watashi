## 2026-09-04 — 共有の廃止・付け替えを管理者が完遂できるようにする

### 機能追加

- 管理画面の共有詳細に「未完了の転送・ごみ箱データ」を表示するようにした。共有の接続先変更・削除が 409 (`share_has_durable_state`) でブロックされる理由を、件数・パス・状態・期限まで画面で確認できる
- 待てば解消するもの (期限待ち) と、待っても解消しないもの (`cleanup_retry` / `purge_retry` = 実体を回収できず再試行中) を区別して表示する
- 「強制解除」ボタンを追加した。まず正規の後片付けを試し、共有へ到達できないものだけ台帳を終端させるため、共有が生きていれば実体ごと回収され、既に停止した共有だけ台帳を諦める
- 実施内容と、回収できず共有上に残るパスを監査ログ `ADMIN_SHARE_RELEASE_DURABLE` に記録する
- 後片付けの再試行に上限を設けた。転送はセッション作成から有効期間 + `TransferV2:CleanupGiveUpDays` (既定 7 日)、ごみ箱は保持期間 + 7 日を過ぎると自動的に諦めて終端する (`cleanup_gave_up`)。停止した共有に対して死んだホストへの接続試行と警告ログが永久に続く問題を解消する

### 互換性 / 検証

- **DB マイグレーションは不要。**`Status` 列には CHECK 制約があり値を増やせないため、終端させた理由は既存の `ErrorCode` 列で区別する (`admin_abandoned` / `cleanup_gave_up`)
- API は追加のみで、既存エンドポイントの挙動は変更していない。旧クライアントとの互換性に影響しない
- `appsettings.json` に `TransferV2:CleanupGiveUpDays` を追加したが、未設定でも既定 7 日で動作するため既存の設定ファイルは変更不要
- 到達可能な場合の実体回収、到達不能な場合の台帳放棄と残骸パスの返却、冪等性、他共有への非波及、再試行の打ち切り、管理画面の配線を自動テストした

### 追加修正 (レビュー指摘)

- 再試行の打ち切りが `committing` の session を除外していた問題を修正。完了復旧は共有へ到達できて初めて成立するため、猶予を過ぎても失敗し続けている場合は復旧の見込みがなく、除外すると永久リトライのまま共有を廃止できない状態が残っていた
- 強制解除中の新規 upload session 作成を、作成側と同じ共有単位ロックで防ぐようにした
- 廃止済みリモートごみ箱の残存台帳を回収するjanitorと強制解除が、項目ロックと共有ロックを逆順で取得して循環待ちになる問題を修正。新規ごみ箱台帳は作られないため、既存台帳を先に項目 → 共有の順で回収し、uploadのみを共有ロック下で解除する

## 2026-09-04 — 拡張子 (種類) による一覧ソート

### 機能追加 / UX 改善

- ファイル一覧に「種類」列を追加し、列見出しのクリックで拡張子順に並べ替えられるようにした。名前・サイズ・更新と同じ操作感で、同じ見出しの再クリックで昇順 ⇄ 降順が切り替わる
- 「種類」列は拡張子をドットなしの大文字 (`XLSX`, `PDF`) で表示する。表示とソートキーが同じ値を使うため、見えている文字と並び順が必ず一致する
- 同じ拡張子の中は常に名前昇順で並べ、降順にしても二次キーは昇順のまま保つ (Windows エクスプローラーと同じ挙動)
- フォルダーと拡張子のないファイル (`README` など) は空欄扱いで、昇順では先頭、降順では末尾にまとまる
- `.tar.gz` `.tar.bz2` `.tar.xz` `.tar.zst` だけは複合拡張子として 1 つにまとめる。`報告書.v1.2.xlsx` のような名前は末尾の `xlsx` だけを拡張子として扱う
- 個人設定の「並び順を記憶する」で拡張子順も保存・復元できるようにした

### 互換性 / 検証

- ソートキー `ext` / `ext_desc` は共有の `FileEntrySort` に追加したため、ローカル (クライアント側ソート) とリモート (サーバー側ソート) で同じ並びになる。**リモートペインはサーバーがソートするため、クライアントとサーバーを同時に更新する必要がある** (旧サーバーは未知キーを既定順として扱うため、押しても並ばない見え方になる)
- DB・API スキーマの変更なし。保存済み `settings.json` も移行不要 (旧クライアントが新しいキーを読んだ場合は既定順に戻るだけ)
- 拡張子の大文字小文字、複合拡張子、拡張子なし・フォルダーの位置、同一拡張子内の名前順、両ペインの列とヘッダ配線、設定の保存・復元を自動テストした

## 2026-08-04 — 初回パスワードを本人が設定する方式へ

Windows 統合認証を有効にした環境では、初期パスワードを管理者が決めて配布する手順を廃止した。ユーザー作成後、本人が初回ログイン時に Windows のログオン情報で本人確認され、自分でパスワードを決める。Windows 認証を利用できない環境向けには、管理者が初期パスワードを発行する代替経路を残した。

### 機能追加

- **パスワード未設定状態を追加** — ユーザー作成時にパスワードを設定せず「初回設定待ち」で登録する。この状態では通常ログイン・自動ログインのいずれも通らない。
  - 未設定を `PasswordHash = NULL` で表さず、誰も知り得ないランダム値の bcrypt ハッシュ (使用不能ハッシュ) + `IsPasswordSetupPending` フラグで表す。NULL 化は SQLite でテーブル再構築を招き、`Users` を Cascade 参照する `UserPermissions` などを巻き添えで削除する危険があるため。判定漏れがあっても照合が false になるだけで済む fail-closed な構造にもなる。
  - migration は `ALTER TABLE ADD COLUMN` 3 本のみ。既存データへの影響なし。
- **Windows 統合認証による本人確認** — `POST /api/auth/win/prepare-login` / `POST /api/auth/win/initialize-password` を追加。「Windows ログオン名 = GID = Watashi ユーザー名」という既存の運用ルールを使い、本人だけが自分の初回パスワードを設定できる。
  - `Auth:WindowsAuth:Mode` (`None` / `IIS` / `Negotiate`) で有効化。**既定は `None`** なので、設定を入れるまで挙動は変わらない。
  - ドメイン照合は `IgnoreDomain` / `AllowList` を設定で切り替え可能。
  - `GET /api/auth/win/whoami` で導入時の疎通確認ができる (既定オフ)。
- **`POST /api/admin/users/{id}/require-setup`** — パスワードを破棄して本人に再設定させる。パスワードを忘れた利用者への対応に、パスワードを人づてに伝える必要がなくなる。
- **クライアントのログインを二段階化** — ID を入力して「次へ」→ 未設定なら初回設定画面、設定済みならパスワード入力。判定 API が使えない環境 (ドメイン非参加・機能無効・旧サーバー・通信不能) では黙って従来のパスワード入力に落ちる。

### セキュリティ

- **ユーザー列挙対策** — 本人確認できた未設定アカウント以外は、不明な ID も通常アカウントも一律「パスワードを入力」を返す。未設定ユーザーへの通常ログインも、存在しないユーザーと同一の応答にした。
- **`IISServerOptions.AutomaticAuthentication` を常に false に** — IIS で Windows 認証を有効にすると、既定 (true) では IIS が `HttpContext.User` を Windows プリンシパルで埋めるため、JWT 無しのリクエストが `RequireAuthorization()` を通過してしまう。
- **CSV の上書きが既存パスワードを再設定しなくなった** — 従来は upsert で既存ユーザーのパスワードを無条件に書き換えていたため、CSV を再取り込みしただけで全員が締め出される事故が起こりうる状態だった。現在は `IsAdmin` のみ更新する。
- **管理者ロックアウト防止の強化** — 「アクティブな管理者」の判定から初回設定待ちの管理者を除外した。ログインできない管理者を数えると、実際に使える最後の管理者を削除・降格できてしまうため。`require-setup` にも同じガードを掛けた。
- 初回設定の要求・本人不一致・成功・拒否をすべて監査ログに記録 (`PASSWORD_SETUP_*`)。初回設定エンドポイントは `login` とは別枠のレート制限にした (Negotiate のハンドシェイクが複数リクエストを消費するため)。

### 修正

- **自動ログインに未設定チェックを追加** — 記憶済み端末が残っていると、未設定ユーザーがパスワード無しでログインできてしまう経路があった。`require-setup` は信頼済み端末と refresh token の両方を失効させる。

### 破壊的変更

- `POST /api/admin/users` は `Password` を受け取らなくなった。
- ユーザー CSV の形式が `Username,IsAdmin` になった。旧形式 (`Username,Password,IsAdmin`) も取り込めるが `Password` 列は無視される。
- ユーザー CSV エクスポートの `MustChangePassword` 列が `PasswordStatus` 列に変わった。

### 文書

- `docs/ADMIN-GUIDE.md` / `docs/manual/admin.html` — 初回パスワード設定の流れ、PW状態の見方、CSV 形式変更、ロックアウト防止の条件を更新。
