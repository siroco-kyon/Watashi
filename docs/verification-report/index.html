4重点確認ポイント（セキュリティ・認証まわり）

特にセキュリティ・内部統制の観点で重要な項目を挙げます。いずれも配布アプリでの実機確認、または自動テストで担保しており、机上確認ではありません。

  • 通信の暗号化：HTTPS接続を前提とし、ユーザー名・パスワード・ファイルが平文で流れないことを確認
  • 権限分離とパストラバーサル対策：フォルダ単位の許可範囲外アクセスを拒否し、「../」を使った範囲外への脱出も確実に拒否されることを確認
  • アカウント保護：規定回数の失敗でのアカウントロック、IP単位のログイン試行回数制限（429応答）を確認
  • リフレッシュトークンの安全性：更新のたびにトークンをローテーションし、失効済みトークンの再提示（盗用の疑い）を検知して関連セッションを失効させることを確認
  • 監査ログ：「誰が・いつ・何をしたか」を自動記録し、CSV出力時の数式インジェクション対策（=で始まる名前の無害化）も確認
  • 資格情報の保護：CIFS接続用パスワードをAES-256-GCMで暗号化して保存し、API応答にも秘密情報が含まれないことを確認
内部統制・監査の観点：権限・セキュリティに関する項目の多くは、実機での確認に加えて自動テスト（xUnit）でも重ねて担保しており、今後の改修でも継続的に回帰を検知できる状態です。

5検証にあわせて実施した改善

検証の実施にあわせて、認証トークン（リフレッシュトークン）まわりの実装を1件改善しました。

観点従来改善後
パスワード変更前トークンの扱い パスワード変更前に発行されたトークンが再提示されると、関連するセッション一式（トークンファミリー）を丸ごと失効させていた 該当トークンのみを失効。パスワード変更後に発行された正規のセッションは維持されるよう調整。トークン盗用時の検知・全失効は従来どおり機能

この改善はテストコード（AuthServiceTests）に反映済みで、今回の検証でも問題は確認されていません。

ポイント：パスワードを変更した利用者が、変更後も他の端末で使い続けている正規セッションを、不必要にログアウトさせてしまう不便を解消しました。不正利用の検知・対処の強さは変えていません。
