# UI・ユーザビリティ改善計画と実装結果

更新: 2026-09-05。以下の改善を実装しました。リモートごみ箱は追加しません。

| 改善 | 実装した動作 |
|---|---|
| FFFTPを意識した転送 | Ctrl+Dは右の選択から左のフォルダーへダウンロード、Ctrl+Uは左の選択から右へアップロード。操作中ペインで方向は変わらない |
| 操作対象の明示 | 操作中のペイン、選択件数、転送先を表示。ボタンとキーは同じ実行条件を使う |
| キーボードでの移動 | F6 / Shift+F6、Ctrl+L、Ctrl+F、Ctrl+Shift+N、絞り込み欄のEsc、F1の操作案内 |
| 誤操作の防止 | 入力欄・IME変換中・長押しでは転送しない。F2は単一選択。複数削除は全対象と件数を確認し、初期選択はキャンセル |
| 一覧の使いやすさ | 同じ場所の再表示では選択・スクロール位置を保持。別の場所に前の選択を引き継がない |
| リモート一覧 | 初回・追加とも2000件。取得済み範囲だけの絞り込みと件数を明示。検索APIの上限500件は維持 |
| 再描画の抑制 | 2000件を1件ずつ通知せず一括反映。既存の一覧仮想化を継続 |
| 転送センター | メイン画面と同時操作できる別ウィンドウ。状態で絞り込み、選択行の詳細を表示。競合待ちだけに上書き・スキップ・別名を提示 |
| メンテナンス表示 | 起動・ログイン・メイン画面で案内。予定／作業中／復旧確認中、案内文・予定時刻・最終確認を表示 |
| 受付停止と復旧 | Serverが新しい業務APIを停止。転送はメンテナンス待機として保持。Server再開と必須更新確認後、その待機分だけを再開 |
| 独立した案内ページ | 静的ページ、状態JSON、配置・更新スクリプトを同梱。APIや配布サイトの停止範囲から分離して配置 |

ショートカットの自由な割り当て、転送センターの埋め込み表示、リモート間コピー・移動UIは今回の対象外です。

## 導入条件

Serverを先に更新してください。旧Serverは2000件の一覧要求を受け付けません。旧Clientからの500件要求は新Serverでも使用できます。DBスキーマ変更はなく、受付停止状態はDB外の私的ファイルで保持します。

API内の状態管理だけなら外部サイトは任意です。API停止中の案内には、停止範囲を分けたHTTPSの静的サイトとServer／Clientの設定が必要です。[メンテナンス導入・更新・復旧手順](../deploy/MAINTENANCE-ROLLOUT-PLAN.md) に配置、権限、切替、切り戻し、実機受入確認をまとめています。本PRはソースと手順の提供であり、本番のIIS・DNS・証明書・サービス構成を変更しません。

## 検証方針

通常テストに加え、2000件の境界・一括通知・既存cursor、複数操作の部分失敗、状態の永続化・公開失敗・競合更新・復旧条件、通信の順序と旧Server、転送中／再起動後の待機を回帰テストします。SMB応答時間、IIS停止中の案内、ClickOnce更新は導入環境で受入確認してください。

操作は[利用者ガイド](USER-GUIDE.md)、運用は[管理者ガイド](ADMIN-GUIDE.md)、APIは[仕様書](SPECIFICATION.md)を参照してください。
