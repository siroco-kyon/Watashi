# ブラックボックス検証 — はじめての方へ

このドキュメントは、**`Watashi_手動検証項目リスト.csv` を使って検証を行う方**向けの手引きです。
プログラムの中身を知らなくても、**配布されたアプリを操作するだけ**でできる検証（＝ブラックボックステスト）の進め方を説明します。

---

## 1. この検証は何のため？

利用者に配る前に、**ClickOnce で配布した Watashi アプリが正しく動くか**を実際の画面操作で確認します。
（コードを読んだり、サーバーの設定をいじったりはしません。画面から見える動きだけを確認します。）

## 2. 用意するもの（前提）

- ✅ **ClickOnce でインストール済みの Watashi クライアントアプリ**（Visual Studio は不要）
- ✅ **中央サーバーが稼働していること**
- ✅ **管理者アカウント**（インフラ担当が bootstrap で発行し、初回変更済みのもの）— 管理者タブの検証に使います
- ✅ できれば **一般ユーザーアカウント**（管理者でない人の見え方の確認に使います）

> サーバーやエージェント（踏み台）の構築、サーバー設定ファイルの編集が必要な項目は、
> **あなたの担当ではありません**（下記「▲」印）。開発・インフラ担当に任せてください。

## 3. CSV の読み方（いちばん大事）

一番左に **「検証区分」** 列を追加しました。まずはこの列で「自分がやるもの」を見分けます。

| 検証区分 | 意味 | あなたがやる？ |
|---|---|---|
| **◎ 配布アプリで検証(ブラックボックス)** | 配布アプリの画面操作だけで確認できる | **これをやります** |
| ▲ 専門環境が必要(開発・インフラ) | サーバー設定・PowerShell・IIS・踏み台などが必要 | やらない（担当へ） |
| − 自動テスト(手動不要) | プログラム側の自動テストで確認済み | やらない |

次に **「必要環境/前提」** 列を見ると、◎ の各項目で何が必要か分かります。

| 必要環境/前提 | どんな準備が要るか |
|---|---|
| ログイン画面で確認 | アプリを起動するだけ（ログイン不要） |
| 要ログイン(一般ユーザー) | 一般ユーザーでログインして操作 |
| 要ログイン(管理者タブ) | 管理者でログインし「管理」タブで操作 |
| 要ファイル共有(CIFS)接続 | 実際のファイル共有サーバーへの接続が必要（未整備なら担当に依頼） |

### おすすめの進め方
1. Excel で CSV を開く
2. **「検証区分」列で `◎` だけに絞り込む（フィルタ）**
3. 「必要環境/前提」で並べ替えると、ログイン不要 → 一般 → 管理者 → ファイル共有 の順にやりやすい
4. 各行の **「操作手順」** どおりに操作し、**「期待される結果」** どおりになるか見る

## 4. あなたがやらない項目（▲）について

`deployment.json`（接続先を固定する設定ファイル）を欠落・空・壊した状態にして試す項目などは、
**正常に配布された ClickOnce アプリでは設定ファイルを書き換えられない**（改ざん検証が働く）ため、
**あなたの検証対象ではありません**。これらは「配布前チェック(発行担当)」として ▲ に分類しており、
発行・開発担当が配布前に確認します。

あなたは **「検証区分」が ◎ の項目だけ**を進めれば大丈夫です。

## 5. 結果の記入

各行の右側に記入欄があります。

- **担当者名**: あなたの名前
- **確認結果**: `OK`（期待どおり） / `NG`（違った） を記入
- `NG` のときは **備考** 欄に「実際どうなったか」を書いてください（スクリーンショットがあるとなお良い）

## 6. つまずいたら

- アプリが起動しない → 「配布設定エラー」が出ていないか確認（＝`deployment.json` の問題）。出ていなければ担当へ連絡。
- 「接続テスト」が失敗する → サーバーが稼働しているか、ネットワークがつながっているかを担当に確認。
- 判断に迷う項目は、無理に `NG` にせず備考に状況を書いて担当に相談してください。
