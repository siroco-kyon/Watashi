# リモート増分一覧・横断検索の運用制約

## 増分一覧

- `GET /api/files/incremental` は、最初の要求で権限確認・SMB 列挙・並び替えを一度だけ行い、2 分間の不変スナップショットを作ります。以後は署名付き cursor から最大 2000 件ずつ返します。
- cursor はユーザー、PermissionId、ホスト、共有、許可ルート、パス、並び順に束縛されます。権限の期限切れ・削除・ルート変更後は継続できません。
- 1 フォルダーは 100,000 件、プロセス全体は 8 スナップショットかつ合計 200,000 件が上限です。上限超過時は応答の `truncated` と `truncationReason` を確認してください。
- サーバー再起動、2 分の期限切れ、容量による退避後は、cursor を使わず最初から一覧を取得してください。

旧Clientの500件要求も受け付けます。2000件対応ClientはServer更新後に配布してください。

## 権限内横断検索

- 検索結果の1ページは最大500件です（一覧の2000件上限とは別）。
- `POST /api/files/search` は、その要求時点で有効な READ 権限の許可ルート配下だけを検索します。包含関係にある許可ルートはまとめ、同じ項目を二重走査しません。
- reparse point は検索結果には表示されますが、その配下へは移動しません。
- 既定値は 25,000 件走査、2,000 件結果、15 秒です。最大値はそれぞれ 100,000 件、2,000 件、30 秒です。
- 一部の許可場所で障害が発生しても、例外文・サーバーアドレス・失敗パス・内部件数は返さず、`scope_unavailable` 警告だけを返して他の場所を続行します。

## 取消とタイムアウト

SMBLibrary 1.5.7 の公開 `QueryDirectory` は、一つのフォルダーを内部で最後まで列挙してから返します。この同期呼び出しを接続プールごと強制切断すると、同じ接続を使う別操作を壊す可能性があるため行いません。そのため取消・時間上限はフォルダー間では即時に反映されますが、非常に大きい単一フォルダーの列挙中だけは、その列挙終了後に反映されます。
