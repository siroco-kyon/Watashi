⛩ Watashi API仕様書

WPFクライアントを介さずファイル操作を行うための、認証・ホスト取得・ファイル操作エンドポイントの正式リファレンスです。使い方の解説はAPI直接利用ガイドを参照してください。

0この仕様書について

本書は、Watashi 中央サーバー（Watashi.Server）が提供する HTTP(S) API のうち、ファイル操作を目的として WPF クライアント以外のツールから利用できるエンドポイント（認証／ホスト・共有・許可パスの取得／ファイル一覧・ダウンロード・アップロード・削除・リネーム・フォルダ作成）を対象とした正式なリファレンスです。

ユーザー・権限・ホストの管理を行う管理者向け API（/api/admin/*）や、Agent との内部通信 API（/api/internal/*）は対象外です（→第11章）。

1全体アーキテクチャ

呼び出し元が WPF クライアントであっても、curl や自作スクリプトであっても、リクエストは中央サーバー内の同じ4段階を通過します。

各段階に対応する実装は次のとおりです。

段階実装失敗時の応答
① 認証ASP.NET Core JWT Bearer ミドルウェア（署名・有効期限・issuer/audience を検証）401
② 認可PermissionService.CanPerformAsync(userId, shareId, path, operation)403
③ 実行NodeRouter（Direct SMB、または Agent への HTTP(S)+mTLS 中継）502 / 503
④ 監査ログAuditLogService.LogAsync(...)（成功・失敗いずれの分岐でも必ず呼ばれる）（記録のみ、応答には影響しない）

2ベースURL・認証方式

項目内容
ベースURL（本番）管理者が指定した中央サーバーの HTTPS URL（例 https://watashi.internal）
ベースURL（開発）http://127.0.0.1:18080（HTTP）／ https://localhost:18443（HTTPS, dev-certs）
認証方式JWT Bearer。Authorization: Bearer <accessToken> ヘッダーを付与
署名アルゴリズムHS256（共有鍵。サーバー側の Jwt:Secret 設定に依存）
Content-TypeJSON ボディは application/json。アップロードは application/octet-stream（生バイト）
文字コードUTF-8
accessToken 有効期限15分（expiresIn 秒 = 900）
refreshToken 有効期限30日。使用のたびに新しい値へローテーション（再利用は不正利用として検知・失効）

JWT のペイロードには次のクレームが含まれます（自分のトークンをデバッグする際の参考）。

クレーム内容
uidユーザーID（数値）
roleAdmin または User
mcpパスワード変更必須フラグ。値 "1" が付与されている間は change-password / logout / refresh 以外の全 API が 403（→第4章）
exp / iss / aud標準クレーム。有効期限・発行者・対象者
API専用の資格情報という概念はない すべてのエンドポイントは、ログイン画面と同じユーザー名・パスワードで認証します。「このユーザーとしてAPIを使いたい」場合は、単純にそのユーザーの資格情報でログインしてください。

3共通エラー形式

エラー時のレスポンスボディは、基本的に次の形式の JSON です（一部 502 系は ASP.NET Core の ProblemDetails 形式）。

JSON
{ "error": "権限がありません。" }
ステータス意味代表的な発生条件
400 Bad Requestリクエスト不正必須パラメータ欠落／数値変換失敗／ホスト・共有が存在しない／リネームで親フォルダ変更
401 Unauthorized未認証トークン欠落・期限切れ・署名不正／ログイン資格情報不一致
403 Forbidden権限不足共有×パスに対する Read/Write/Delete/Rename 権限が無い／許可ルート自体への破壊的操作／アカウントロック中／mcp クレーム保持中に対象外 API を呼んだ
413 Payload Too Largeアップロードサイズ超過Kestrel/IIS の上限（→利用ガイド第11章）を超えるアップロード。アプリに届く前に拒否される
429 Too Many Requestsレート制限超過login／refresh の IP 単位回数制限超過
502 Bad GatewayCIFS側エラーCIFS の I/O エラー・認証エラー（IOException / UnauthorizedAccessException）
503 Service Unavailable実行ノード到達不可Agent に接続できない（NodeUnreachableException）
500 Internal Server Error想定外のエラー詳細はマスクされ「内部エラーが発生しました。」のみ返る

4Auth API（認証）

すべて /api/auth 配下。

POST/api/auth/login認証不要

ユーザー名・パスワードでログインし、アクセストークン一式を発行します。IP単位で 1分間 10回（既定値、Auth:LoginPerMinutePerIp）までのレート制限あり。

リクエストボディ

フィールド型必須説明
usernamestring○ユーザー名
passwordstring○パスワード
windowsUsernamestring?-クライアントの Windows ログオン名。監査・別人ログイン検知用（省略可）
machineNamestring?-クライアントの端末名。監査・端末変更検知用（省略可）

レスポンス 200 (LoginResponse)

{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "base64...",
  "refreshTokenId": "guid",
  "expiresIn": 900,
  "mustChangePassword": false,
  "passwordExpiresInDays": 87,
  "passwordWarningDays": 14,
  "idleMinutes": 30
}

エラー

ステータス条件
400username / password が空
401ユーザー名またはパスワードが不一致
403連続失敗によりアカウントロック中
429同一IPからのレート制限超過
POST/api/auth/refresh認証不要

accessToken を更新します。呼び出しのたびに refreshToken / refreshTokenId も新しい値へローテーションされます。IP単位で1分間 60回（既定値）まで。

リクエストボディ (RefreshRequest)

フィールド型必須
refreshTokenIdstring○
refreshTokenstring○

レスポンス 200 (RefreshResponse)

{
  "accessToken": "eyJhbGciOi...",
  "expiresIn": 900,
  "mustChangePassword": false,
  "refreshToken": "base64...(新しい値)",
  "refreshTokenId": "guid(新しい値)"
}

エラー

ステータスerror 値意味
400-必須フィールド欠落
401password_changedパスワードが変更済み
token_reuse_detected失効済みトークンの再利用を検知（ファミリー全失効）
account_lockedアカウントロック中
device_revoked信頼デバイスが失効済み
429-レート制限超過
POST/api/auth/logout要 Bearer

指定した refreshTokenId を失効させます。自分（トークンの持ち主）が所有するものだけ失効できます。

リクエストボディ (RefreshRequest)

フィールド必須備考
refreshTokenId○-
refreshToken-任意。指定した場合は値も突合される

レスポンス

204 No Content

エラー

ステータス条件
400refreshTokenId 欠落
401Bearer トークン欠落・不正
POST/api/auth/change-password要 Bearer

パスワードを変更し、新しいトークン一式を発行します。mcp クレーム（要パスワード変更）を持つトークンでも呼び出せる数少ないエンドポイントの一つです。

リクエストボディ (ChangePasswordRequest)

フィールド必須
currentPassword○
newPassword○

新パスワードのポリシー：12文字以上、かつ英大文字・英小文字・数字・記号をそれぞれ1文字以上含むこと。

レスポンス 200 (LoginResponse と同型)

新しい accessToken / refreshToken / refreshTokenId が発行されます。旧トークンは即座に無効になるため、呼び出し側は必ず新しい値に置き換えてください。

エラー

ステータス条件
400現在のパスワード不一致、または新パスワードがポリシー未達
401Bearer トークン欠落・不正
本書の対象外の Auth エンドポイント /api/auth/auto-login と /api/auth/trust-device は、WPF クライアントの「このPCを記憶する」機能（Windowsユーザー名＋端末固有トークンでの自動ログイン）専用です。
/api/auth/win/prepare-login と /api/auth/win/initialize-password は、利用者が初回パスワードを自分で設定するための経路で、Windows 統合認証（Negotiate）を要求します。
ファイルをAPIで操作する用途では、通常の /api/auth/login のみで完結します。
パスワード未設定のアカウントはログインできません 管理者が作成した直後のユーザーは「初回設定待ち」で、本人が Watashi クライアントから初回パスワードを設定するまで /api/auth/login は 401 Unauthorized を返します（存在しないユーザー名と同じ応答です）。API 連携用のアカウントを使う場合は、先にクライアントで初回設定を済ませるか、管理者に初期パスワードを発行してもらってください。

5Hosts API（アクセス可能な場所の取得）

すべて /api/hosts 配下、要 Bearer。ログイン中のユーザーに権限が割り当てられている範囲のみ返されます（他ユーザーの権限は見えません）。

GET/api/hosts要 Bearer

アクセス可能なホスト一覧。

[ { "id": 1, "name": "経理部ファイルサーバ", "description": "..." } ]
GET/api/hosts/{hostId}/shares要 Bearer

指定ホスト配下でアクセス可能な共有一覧。

[ { "id": 1, "shareName": "documents", "displayName": "経理部ドキュメント" } ]
GET/api/hosts/{hostId}/shares/{shareId}/locations要 Bearer

指定ホスト・共有内で、自分に割り当てられている許可パス（LocationDto）一覧。

[ {
  "permissionId": 12, "hostId": 1, "shareId": 1,
  "path": "/dept-A", "displayName": "経理部 2026",
  "hostName": "経理部ファイルサーバ", "shareName": "経理部ドキュメント",
  "permissions": { "read": true, "write": true, "delete": false, "rename": false }
} ]
GET/api/hosts/catalog要 Bearer

上記3つを1回のリクエストに集約したエンドポイント。hostId / shareId の組み合わせを調べる際は、まずこれを呼ぶのが最も効率的です。

{
  "hosts": [ {
    "id": 1, "name": "経理部ファイルサーバ", "description": "...",
    "shares": [ {
      "id": 1, "shareName": "documents", "displayName": "経理部ドキュメント",
      "locations": [ /* LocationDto[] （上記locationsと同じ形） */ ]
    } ]
  } ]
}
アクセスできる場所が無い場合 hosts は空配列 [] になります（エラーにはなりません）。

6Files API（ファイル操作）

すべて /api/files 配下、要 Bearer。各操作は「共有 × パス × 操作種別（Read/Write/Delete/Rename）」の権限チェックを通過する必要があります（→第7章）。存在しない hostId/shareId の組み合わせは 400 になります。

ファイル一覧

GET/api/files要 Read
クエリ必須説明
hostId○int
shareId○int
path-既定 /。共有内の絶対パス
page-1以上で1ページ200件。0以下または省略時は全件を1回で返却
sort-name / name_desc / date / date_desc / size / size_desc。省略時はディレクトリ優先＋名前昇順

レスポンス 200 (FileListResponse)

{
  "currentPath": "/dept-A",
  "entries": [
    { "name": "..", "type": "parent", "canGoUp": true },
    { "name": "reports", "type": "directory", "size": null, "modifiedAt": "2026-06-01T00:00:00Z" },
    { "name": "budget.xlsx", "type": "file", "size": 48213, "modifiedAt": "2026-07-10T09:30:00Z", "isReparsePoint": false }
  ],
  "page": 1,
  "totalCount": 2
}

entries の先頭には常に type: "parent"（..）が入ります。canGoUp が false の場合、そこが自分の許可パスの最上位であることを示します。

ダウンロード

GET/api/files/download要 Read
クエリ必須
hostId / shareId / pathすべて必須

レスポンス 200

ファイルの生バイトをそのままストリーミング返却。Content-Type: application/octet-stream、Content-Disposition: attachment; filename*=UTF-8''<ファイル名>。サイズが判明する場合は Content-Length も付与されます。

アップロード

POST/api/files/upload要 Write
クエリ必須説明
hostId / shareId○-
path○保存先のフルパス。既存の同名ファイルは上書きされる

リクエストボディ：アップロードするファイルの生バイト列（application/octet-stream）。マルチパートではありません。

レスポンス

204 No Content

サイズ上限 アプリ側の既定上限は 10GB ですが、IIS でホストしている場合は web.config の requestFiltering がより手前で効くため、実効上限は約4GB（uint の最大値）です。超過時はアプリに届く前に 413 になります。

削除

DELETE/api/files要 Delete
クエリ必須
hostId / shareId / pathすべて必須

レスポンス：204 No Content。自分の許可パスのルート自体を指定した場合は 403（permission_root、誤操作防止のためのサーバー側ガード）。

リネーム

POST/api/files/rename要 Rename

リクエストボディ (RenameRequest)

フィールド型必須
hostId / shareIdint○

newPathstring○

レスポンス：204 No Content。次の追加ルールがあります。

状況応答

newPath への Write 権限が無い403

7権限モデルとの関係

すべての Files API は、呼び出し前に PermissionService.CanPerformAsync(userId, shareId, path, operation) を通過します。operation は次の4種類で、各ユーザーは共有×パスの単位で個別に許可されます。

操作必要なエンドポイント備考
READ一覧・ダウンロードこれが無いと一覧取得もダウンロードも 403
WRITEアップロード・フォルダ作成・リネーム先パス-
DELETE削除許可パスのルート自体は Delete があっても削除不可
RENAMEリネーム元パス実行には RENAME（旧パス）＋ WRITE（新パス）の両方が必要

どのユーザーがどの共有×パスにどの権限を持つかは、管理コンソールの「ユーザー権限」タブで管理されます（本書の対象外。管理者向けには docs/manual/admin.html を参照）。

8監査ログ対応表

各エンドポイントの呼び出しは、成功・失敗を問わず AuditLog テーブルに1件記録されます。

エンドポイントOperation コード
GET /api/filesLIST
GET /api/files/downloadDOWNLOAD
POST /api/files/uploadUPLOAD
DELETE /api/filesDELETE
POST /api/files/renameRENAME
POST /api/files/mkdirMKDIR

記録される主なフィールド：Timestamp, UserId/Username, Operation, HostId/ShareId/Path/TargetPath（リネーム時）, Result（成功/失敗）, ErrorMessage, ClientIp/ClientHostname/Protocol, BytesTransferred, DurationMs, ExecutionNodeId, UsedPermissionId。

失敗時の代表的な ErrorMessage（監査ログ上の理由コード）：denied（権限不足）、permission_root（許可ルートへの破壊的操作）、parent_changed（リネームでフォルダ変更）、canceled（クライアント切断）。

11本書の対象外（参考）

次の API 群も中央サーバーに存在しますが、「ファイルをAPIで直接操作する」という本書の目的の範囲外のため扱いません。

API群用途認証
/api/auth/auto-login, /api/auth/trust-deviceWPFクライアントの「このPCを記憶する」自動ログイン端末トークン
/api/admin/*ユーザー・ホスト・共有・権限・実行ノード・監査ログ・システム設定の管理Bearer + Admin ロール
/api/internal/*中央サーバー ⇔ Agent 間の内部通信mTLS クライアント証明書または共有シークレット

管理者向け操作の詳細は docs/manual/admin.html（管理者マニュアル）を参照してください。
