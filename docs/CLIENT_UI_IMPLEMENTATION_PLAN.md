# クライアント UI 改修 実装計画

最終更新: 2026-08-23（当時の実装記録）

2026-09-05追記: 一覧の500件単位など、以下は当時の仕様です。現在は2000件単位です。後続のショートカット・メンテナンス改善は[改善計画と実装結果](UI_USABILITY_IMPROVEMENT_PLAN.md)を参照してください。

この文書は、今回のクライアント UI 改修で合意した方針を実装中に見失わないためのチェックリストです。
仕様変更が必要になった場合は、コードより先にこの文書を更新します。

## 変更範囲

- クライアントとクライアント向け文書だけを変更する。
- サーバー、Agent、DB、共有 API 契約は変更しない。
- クライアントは .NET 10 WPF (`net10.0-windows`) を対象にする。
- リモート一覧は既存サーバーの上限内で、初回 500 件、追加読込 1 回につき 500 件とする。

## 1. .NET 10 とテーマ基盤

- [x] クライアント本体と ClickOnce プロファイルを `net10.0-windows` に更新する。
- [x] WPF 標準 `ThemeMode` を基盤に `Light` / `Dark` を切り替える。
- [x] テーマ設定を利用者の `settings.json` に保存し、次回起動時に復元する。
- [x] テーマ変更はメイン画面右上の月／太陽アイコンだけで行い、ログイン画面には変更操作を置かない。
- [x] 旧 `System` 設定は、更新時点の Windows の見た目を一度だけ `Light` / `Dark` へ変換して保存する。
- [x] Watashi 固有の背景、文字、境界、朱色アクセントをライト／ダーク両方で定義する。
- [x] 既存のハイコントラスト用システム色を優先する。
- [x] ContextMenu、ComboBox のドロップダウン、ToolTip、ScrollBar、DatePicker を確認し、Watashi の独自スタイルが標準 Fluent テーマを妨げる箇所だけ補正する。
- [x] Windows 所有のファイル／フォルダー選択、タイトルバーのシステムメニュー、緊急 MessageBox は OS 表示のままとする。

受け入れ条件:

- 月／太陽ボタンを押すとライト／ダークが切り替わり、開いている Watashi ウィンドウへ即時反映される。
- 通常動作では Windows テーマへ追従せず、選択肢はライト／ダークの 2 つだけとする。
- ログイン画面は保存済みテーマで表示するが、テーマ変更操作は表示しない。
- 再起動後も明示的に選択したモードを復元する。
- アプリ内の右クリックメニューがダークモードで白背景にならない。

## 2. ブランディング資料

- [x] `docs/BRANDING.md` の色変更手順をライト／ダーク両パレット対応へ更新する。
- [x] `docs/BRANDING.html` を Markdown 版と同じ内容へ更新する。
- [x] ブランド色、ベクターアイコン、`.ico` 生成スクリプトの対応関係を明記する。
- [x] ライト／ダーク／ハイコントラストの確認項目を追加する。

## 3. メイン画面の最大化と復元

- [x] 最大化直後に `WindowState.Normal` へ戻す回避処理を廃止する。
- [x] 現在のモニターの作業領域を `WM_GETMINMAXINFO` で Windows に通知する。
- [x] Windows の最大化状態を維持し、復元ボタンで元の位置とサイズへ戻せるようにする。

受け入れ条件:

- 最大化で現在のモニターの作業領域全体を使用する。
- 復元で最大化前のサイズへ戻る。
- 複数モニターと異なる DPI で位置やサイズがずれない。

## 4. リモート一覧 500 件単位

- [x] 初回取得を 200 件から 500 件へ変更する。
- [x] 「さらに読み込む」1 回の追加件数も 500 件へ変更する。
- [x] 500 件以下では追加ボタンを表示せず、501 件以上では表示する。
- [x] 横断検索の件数やサーバーコードは変更しない。

## 5. 接続場所ツールチップ

- [x] 接続場所へホバーしたとき、現在選択中の表示名、ホスト、共有、許可ルートを全文表示する。
- [x] 接続先の変更時に即時更新する。
- [x] 未選択時の案内と UI Automation の HelpText を用意する。

## 6. フォルダー移動時の絞り込み初期化

- [x] 実際に別フォルダーへの移動が成功したときだけ `FilterText` を空にする。
- [x] ローカル／リモートの両ペインを対象にする。
- [x] 戻る、進む、親へ移動、ダブルクリック、パス入力、保存場所からの移動を共通処理で扱う。
- [x] F5 と同一パスの再読み込みでは絞り込みを保持する。
- [x] 列ソート (`SortKey`) は常に保持し、新しいフォルダーにも同じ並び順を適用する。

## 7. 検証と文書

- [x] 設定の既定値、正規化、保存／復元を自動テストする。
- [x] テーマリソースと XAML の契約テストを追加する。
- [x] 500 件ページングのクライアント契約をテストする。
- [x] 最大化ヘルパーの座標計算を単体テスト可能な形に分離する。
- [x] 手動検証 CSV、ユーザーガイド、仕様、変更履歴を更新する。
- [x] 全自動テストとクライアントの互換ビルドを実行する。

## 実装環境上の注意

現在の作業環境では .NET 10 SDK を利用できるため、クライアントは既定の `net10.0-windows` で直接ビルド・実画面検証する。

## 実装後の検証結果

- `dotnet build Watashi.sln -c Release` で .NET 10 クライアントを含む全体ビルドが警告 0 / エラー 0。
- xUnit は 633 件すべて成功。
- 変更した XAML はコンパイルに成功し、テーマパレット、旧 `System` 移行、月／太陽アイコン、ログイン画面からの操作削除を自動テスト済み。
- `Watashi.Server` / `Watashi.Agent` / `Watashi.Shared` と API 契約は変更していない。
- 隔離したローカルサーバーへログインし、ホーム画面の月ボタンでライトからダークへ切り替わり、太陽ボタンと「ライトモードに切り替え」の読み上げ名へ更新されることを実画面で確認。
- ダークのまま再起動して設定が復元され、ログイン画面にはテーマ変更操作が表示されないことを実画面で確認。
